## 문제 요약

`runSecretsApply` 의 write 모드 커밋 블록(`src/secrets/apply.ts:835-855`)은 한 논리 트랜잭션(plaintext
자격증명 → SecretRef 마이그레이션)에서 config.json 을 `replaceConfigFile` 로 먼저 커밋하고, 이어서
N개 `auth-profiles.json` + legacy auth-json + `.env` 를 for 루프로 `writeTextFileAtomic` 순차
커밋한다. 각 파일은 개별 atomic 이지만 **파일 간 트랜잭션/저널/단일 lock 경계가 없다**. config 커밋이
성공한 뒤 satellite write 루프 N번째에서 fs fault(ENOSPC / EACCES — 0o700 부모 dir 생성 실패 /
EIO)로 throw 하면 config=ref, 일부 auth-store=plaintext 로 발산한다. catch 의 롤백은 best-effort
(`restoreFileSnapshot` 이 `writeTextFileAtomic` 를 swallowing try/catch 안에서 호출, apply.ts:846-853)
라, throw 를 유발한 동일 fault 조건이 복원 write 도 실패시키면 발산이 영속한다. auth-profiles.json /
auth-json / .env 는 자격증명의 영속 SoT 라 재생성 불가 → (a) config=ref / auth-store=plaintext 잔존
→ 평문 자격증명 scrub 실패(유출 표면), (b) config=원복 / auth-store=scrub → ref 미반영으로 자격증명
로드 실패. pre-sol proof(`PROOF-CAND-048-pre-20260529-070756.md`, scenario `proof-CAND-048`):
defect 빌드에서 store#2 commit ENOSPC 주입 시 config=plaintext / store#1=ref / store#2=plaintext
로 `diverged=true`, migratedStores 1/2. control(fault 없음)은 2/2 ref, diverged=false 로
결함이 fault 주입에서만 발현됨을 baseline 확보.

같은 커밋 경로의 FIND-002(apply 의 auth-store write 가 AUTH_STORE_LOCK 미획득 → 동시 OAuth refresh
lost-update)는 fix 표면이 구별되어 자식 task 로 분리(frontmatter cross_refs 참조). 본 SOL 은 FIND-001
의 파일 간 트랜잭션 경계 부재를 primary 로 닫는다.

## 해결 후보

### 후보 1 — stage-all-temp-then-rename (chosen)

- **요약**: 커밋을 2-phase 로 재구성. **Phase A(prepare/stage)**: config 를 포함한 모든 대상 파일의
  최종 내용을 각자의 디렉터리에 temp 파일(`*.tmp`)로 작성한다 — 디스크/권한 fault 는 거의 전부 이 단계의
  `open`/`write` 에서 발현된다. Phase A 중 어느 하나라도 실패하면 이미 만든 temp 파일을 모두 unlink 하고
  **아무 실파일도 건드리지 않은 채** throw → 부분 커밋 0. **Phase B(commit)**: 모든 staging 이 성공한
  뒤에만 각 temp 를 실파일로 `rename` 한다. rename 은 같은 파일시스템 내 메타데이터 연산이라 write 대비
  실패 확률이 현저히 낮아 부분 커밋 창이 사실상 닫힌다. config(`replaceConfigFile`)도 이 staging 규약
  안으로 끌어와 satellite 와 같은 phase 에서 검증되게 한다(또는 config 를 마지막 rename 으로 두어 satellite
  rename 이 전부 성공한 뒤에만 config 가 전진하도록 순서 보장).
- **change_scope**: S (1 file 중심, ~80-130 line: 커밋 블록 재구성 + temp 작성/일괄 rename 헬퍼).
- **files_touched**:
  - `src/secrets/apply.ts:808-855` (커밋 블록 2-phase 재구성), `src/secrets/apply.ts:727-755`
    (snapshot/write 헬퍼 인접 — staging 헬퍼 추가).
  - 필요 시 `src/secrets/shared.ts`(`writeTextFileAtomic` 가 이미 temp+rename 이므로 그 내부의
    stage/commit 분리 진입점을 노출하거나, fs-safe `replaceFileAtomicSync` 의 prepare/commit
    seam 사용 — 단 fs-safe 는 외부 패키지라 in-tree staging 헬퍼로 자체 구현 우선).
  - (test) `src/secrets/apply.test.ts` 신규 it.
- **tradeoff**:
  - 장점: 부분 커밋 창을 write→rename 으로 축소해 결함의 main trigger(satellite write fault)를
    구조적으로 차단. best-effort 롤백의 신뢰성 문제(복원 write 도 실패)를 우회 — 애초에 실파일을 안 건드림.
    config↔auth-store all-or-nothing 에 근접. nativeRuntime/외부 contract 미변경.
  - 단점: 완전한 원자성은 아님(Phase B 의 여러 rename 사이에 프로세스 crash 시 일부만 rename 가능 —
    단 rename 은 거의 즉시이고, write 대비 fault window 가 수십~수백배 작다). 진짜 crash-원자성은 단일
    저널/디렉터리 rename 이 필요하나 그건 M+ 이고 secrets 파일이 여러 디렉터리에 흩어져 있어 단일 dir
    rename 불가. PR 적정 크기 유지를 위해 "staging 으로 write-fault 창 제거 + rename-only commit"
    까지를 scope 로 한다(잔여 multi-rename crash 창은 PR 본문 "What was not tested" 에 명시).
  - chmod 0o400/0o500 가 무시되는 root CI 환경에서 fault 주입이 안 먹을 수 있어, 재현 테스트가 spy
    폴백을 가질 수 있게 가이드(추천 섹션 참조).

### 후보 2 — pre-flight-writability-probe-then-current-commit

- **요약**: 현재 커밋 순서는 그대로 두되, 커밋 직전에 모든 대상 경로(부모 dir 포함)에 대해 쓰기 가능성/여유
  공간을 probe(예: temp 파일 1개 작성·삭제)한 뒤, 하나라도 실패하면 커밋 시작 전에 throw.
- **change_scope**: XS (커밋 블록 앞 probe 루프 ~20 line).
- **tradeoff**: 구현 작고 대부분의 ENOSPC/EACCES 케이스를 커밋 전에 거른다. 그러나 probe↔commit 사이의
  TOCTOU(probe 통과 후 디스크가 차거나 권한 변경)를 닫지 못하고, EIO/하드웨어 fault 처럼 write 시점에만
  나는 fault 는 여전히 부분 커밋을 낼 수 있다. "거의 막는다"는 결함의 근본(파일 간 경계 부재)을 남긴다 →
  best-effort 롤백 의존이 그대로. 후보 1 대비 보장 약함.

### 후보 3 — durable-rollback-with-verified-restore

- **요약**: 커밋 순서/방식은 유지하되 catch 의 롤백을 강화 — 각 `restoreFileSnapshot` 후 디스크를 다시
  읽어 snapshot 과 일치하는지 verify, 실패 시 retry(제한) + 최종 실패하면 단순 swallow 대신 명시적
  "INCONSISTENT STATE" 에러 코드를 던져 사용자에게 수동 복구 경로를 노출(에러에 잔존 발산 파일 목록 포함).
- **change_scope**: S (catch 블록 재작성 + 에러 타입 ~60 line).
- **tradeoff**: 발산을 "은밀히 영속"에서 "큰소리로 실패 + 복구 안내"로 바꿔 유출/로드실패의 silent 위험은
  줄이나, throw 를 유발한 동일 fault(디스크 가득/권한)가 retry 도 실패시키면 결국 발산이 남는다(근본 미해결).
  사용자에게 책임 전가. 후보 1(부분 커밋 자체를 안 만듦)이 우월. 단 후보 1 과 보완 결합 가능(staging 으로도
  못 막은 Phase B 중간 실패 시 이 명시 에러를 던지는 형태).

### 커밋 메시지 초안
```
fix(secrets): stage all files then commit so apply never half-migrates

runSecretsApply's write-mode commit block (src/secrets/apply.ts:835-855)
migrates plaintext credentials to SecretRefs across config.json plus N
auth-profiles.json / legacy auth-json / .env files. It commits config
first via replaceConfigFile, then writes the satellite files in a plain
for-loop with no cross-file transaction boundary. If a satellite
writeTextFileAtomic faults mid-loop (ENOSPC / EACCES from a 0o700 parent
mkdir / EIO), config is already migrated to refs while some auth-stores
still hold plaintext, leaving the two stores diverged. The catch rolls
back best-effort only (restoreFileSnapshot calls writeTextFileAtomic
inside a swallowing try/catch), so the same fault that caused the throw
can also fail the restore and make the divergence permanent. The
satellite files are credential SoT (OAuth/api_key tokens), so the result
is either plaintext left un-scrubbed on disk or refs that no longer
resolve.

Restructure the commit into stage-then-commit: write every target file
(config + satellites) to a temp file first, fail and clean up the temps
without touching any real file if staging throws, and only after all
staging succeeds rename the temps into place. The fault-prone write step
no longer touches live files, so a faulting apply leaves all stores in
their original (un-migrated) state instead of a half-migrated mix.

Repro: src/secrets/apply.test.ts injects a real read-only parent dir on a
second auth-store; before this change config advances to refs while that
store keeps plaintext (diverged); after, nothing advances.

AI-assisted: drafted with claude code (claude-opus-4-8).
```
