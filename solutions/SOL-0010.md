## 문제 요약

`createPluginToolsMcpHandlers.callTool` (`src/mcp/plugin-tools-handlers.ts:47`)
이 MCP SDK 가 제공하는 cancellation signal 을 받지 않는다. 상위
`createToolsMcpServer` (`src/mcp/tools-stdio-server.ts:16-18`) 의
`setRequestHandler(CallToolRequestSchema, async (request) => ...)` wrapper 가
두 번째 인자 `extra: RequestHandlerExtra` (signal: AbortSignal 포함) 를 통째로
무시하고, callTool 자체도 signal 파라미터를 받지 않는 형태로 설계되어 있다.
결과적으로 `tool.execute(toolCallId, params, signal?, onUpdate?)`
(`src/agents/tools/common.ts:22-28`) 의 4번째 인자 signal 이 영구히
undefined.

MCP host (Claude Code SDK / Codex / ACPX bridge) 가 `notifications/cancelled`
를 보내면 SDK 의 `Protocol._onresponse`/`_oncancellednotification` 이 내부
`AbortController.abort()` 를 호출하여 `extra.signal.aborted=true` 가 되지만,
handler 가 그 signal 을 받지 않아 in-flight `tool.execute` 는 통보 못 받고
자체 timeout (없으면 영원히) 까지 hang. host 가 후속 SIGKILL 로만 종료하면
graceful cleanup (DB rollback / browser temp file / network socket FIN /
in-flight stream backpressure release) skip — 자원이 OS 회수에 의존.

`PROOF-CAND-026-pre-20260515-002424.md` 의 wire-level e2e 측정 (production
bundle `dist/mcp/plugin-tools-serve.js` + 실 stdio MCP transport + 실 SDK
Client + `notifications/cancelled`) 에서 `signalDefined=false`,
`executeInvoked=1`, `elapsedMs=501` (handler 가 cancel 받았는데도 끝까지 실행)
로 결함 직접 측정.

scope-down (cross-review 평균 0.84, critical-devil scope-down high) 으로
FIND-001 (`void server.close()` 의 in-flight drain 부재) 은 abandon — SDK
`Protocol._onclose` 가 transport.onclose 시 `_requestHandlerAbortControllers`
unconditional abort + `protocol.js:369-372` 의 post-handler abort check 가
응답 송신 자체 skip 하므로 drain/await close 추가 효과 미미. 본 SOL 은
**FIND-002 단독** 처리.

```ts
import { describe, expect, it } from "vitest";
import { Client } from "@modelcontextprotocol/sdk/client/index.js";
import { InMemoryTransport } from "@modelcontextprotocol/sdk/inMemory.js";
import type { AnyAgentTool } from "../agents/tools/common.js";
import { createToolsMcpServer } from "./tools-stdio-server.js";

describe("plugin-tools handler forwards host cancellation to tool.execute", () => {
  it("aborts in-flight tool.execute when client cancels the request", async () => {
    let observedSignal: AbortSignal | undefined;
    let abortFired = false;

    const probeTool = {
      name: "probe",
      description: "test",
      inputSchema: { type: "object", additionalProperties: true },
      execute: async (
        _toolCallId: string,
        _params: unknown,
        signal?: AbortSignal,
      ) => {
        observedSignal = signal;
        await new Promise<void>((resolve) => {
          if (!signal) {
            // without fix: signal undefined, test hangs until vitest timeout.
            return;
          }
          if (signal.aborted) {
            abortFired = true;
            resolve();
            return;
          }
          signal.addEventListener(
            "abort",
            () => {
              abortFired = true;
              resolve();
            },
            { once: true },
          );
        });
        return { content: [{ type: "text", text: "done" }] };
      },
    } as unknown as AnyAgentTool;

    const server = createToolsMcpServer({ name: "test", tools: [probeTool] });
    const [clientTransport, serverTransport] =
      InMemoryTransport.createLinkedPair();
    const client = new Client(
      { name: "test-client", version: "0.0.0" },
      { capabilities: {} },
    );

    await Promise.all([
      server.connect(serverTransport),
      client.connect(clientTransport),
    ]);

    const controller = new AbortController();
    const callPromise = client.callTool(
      { name: "probe", arguments: {} },
      undefined,
      { signal: controller.signal },
    );

    // Give the server handler one tick to invoke tool.execute.
    await new Promise((r) => setTimeout(r, 20));
    expect(observedSignal, "handler received signal from extra").toBeInstanceOf(
      AbortSignal,
    );
    expect(observedSignal?.aborted).toBe(false);

    controller.abort();

    await expect(callPromise).rejects.toBeDefined();
    expect(abortFired, "tool.execute observed signal.abort event").toBe(true);

    await client.close();
    await server.close();
  });
});
```

RED 기준 (수정 전): `observedSignal` 이 `undefined` → 첫 `expect` 실패 (또는
test timeout). GREEN 기준 (수정 후): handler 가 `extra.signal` 을 전달 →
`observedSignal` 이 AbortSignal 인스턴스, `controller.abort()` 후
`abortFired=true`, callPromise reject.

이식 가이드: openclaw repo 에 `src/mcp/plugin-tools-handlers.cancel.test.ts`
로 추가. `pnpm test src/mcp/plugin-tools-handlers.cancel.test.ts` 로 단독
실행 가능. CI 의 default vitest 프로필이 src/mcp/**/*.test.ts 를 picks up.

### 커밋 메시지 초안
```
fix(mcp): forward host cancellation signal to plugin tool.execute

The plugin-tools MCP server (createToolsMcpServer / createPluginToolsMcpHandlers)
dropped the RequestHandlerExtra.signal exposed by the SDK on every callTool
invocation. Host cancellation (notifications/cancelled) and transport close
both fire the SDK's per-request AbortController, but the handler ignored
the extra argument and called tool.execute without its optional signal
parameter, so in-flight tool work hung until SIGKILL.

Thread extra.signal through callTool to tool.execute so signal-aware tools
(memory-lancedb recall, browser navigation, shell exec, etc.) can release
external resources when the host cancels.

AI-assisted: drafted with claude code (claude-opus-4-7).
```
