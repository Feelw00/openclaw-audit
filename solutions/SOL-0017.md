## 문제 요약

`migrateLegacySessions` (`src/infra/state-migrations.ts:1136-1262`) 는 legacy sessions
디렉터리를 target `agents/{id}/sessions/sessions.json` 으로 병합한다. target 파일이
손상(JSON5 파싱 실패)이면 `readSessionStoreJson5` (state-migrations.fs.ts:47-58) 가
read/parse 예외를 try/catch-swallow 해 `{store:{}, ok:false}` 를 반환하고, 호출부는
`targetStore = {}` 로 진행한다. 그 결과 `merged = {...빈 target, ...legacy}` = legacy-only
가 된다. save 게이트는 OR 조건 `(legacyParsed.ok || targetParsed.ok)` (:1197-1199) 이라
`legacyParsed.ok=true` 만으로 통과하고, `targetParsed.ok` 는 save 분기 어디에서도
검사되지 않는다 (:1197-1216). 따라서 손상되었지만 디스크에 남아있던 원본 target 이
`saveSessionStore` (:1209) 로 legacy-only 병합본에 의해 원자적으로 덮어써진다. legacy 에
대응 키가 없던 target 세션 레코드는 영구 소실되고, 손상 파일을 수동 복구할 마지막 기회도
사라진다. legacy 손상은 :1191 warn + :1239 `legacyParsed.ok` 가드(삭제 차단)로 보호되나
target 손상은 비대칭으로 무방비다. cold doctor/startup 경로(process 당 `autoMigrateChecked`
1회)지만 손상 직후 사용자가 복구를 가장 원하는 시점에 마지막 사본을 비가역 파괴한다.

pre_sol_proof (`PROOF-CAND-049-pre-20260529-070637.md`, base c559776c51) 가 without-fix
빌드에서 trials=2 모두 `overwritten=true`, `targetCorruptBytesSurvived=false`,
`targetOnlyKeyPresent=false`, `warnedAboutTargetCorruption=false` 로 결함을 직접 재현했다
(afterKeys 에 legacy 키만 남고 target-only 키 소실, 경고 없음).

본 SOL 은 CAND-049 epic 의 scope-down 으로 FIND-001 만 다룬다. FIND-002
(`runLegacyStateMigrations` 멀티스토어 비원자 시퀀스 → split state) 는 별도 자식 task.

## 재현 테스트

`src/infra/state-migrations.test.ts` 의 기존 `describe("state migrations", ...)` 블록에
신규 `it(...)` 추가. 기존 happy-path 테스트(:205 `runs legacy state migrations ...`)와
동일하게 public 진입점 `runLegacyStateMigrations` 를 호출하되, target sessions.json 을
trailing garbage 로 손상시키고 legacy 에 없는 target-only 키를 포함시킨다. 수정 전엔
손상 target 이 legacy-only 로 덮어써져 target-only 키가 소실(RED), 수정 후엔 손상 파일이
보존되고 경고가 푸시되며 덮어쓰기가 일어나지 않는다(GREEN).

```ts
it("preserves a corrupt target session store instead of overwriting it with legacy-only data", async () => {
  const { root, stateDir, env, cfg } = await createLegacyStateFixture();

  const targetStorePath = path.join(
    stateDir,
    "agents",
    "worker-1",
    "sessions",
    "sessions.json",
  );
  // target sessions.json is corrupt (trailing garbage → JSON5.parse fails) and
  // holds a target-only key that has no legacy counterpart.
  const corruptBytes = `${JSON.stringify({
    "agent:worker-1:desk:target-only": { sessionId: "target-only-session", updatedAt: 99 },
  })}\n<<<corrupt trailing garbage>>>`;
  await fs.writeFile(targetStorePath, corruptBytes, "utf8");

  const detected = await detectLegacyStateMigrations({
    cfg,
    env,
    homedir: () => root,
  });
  const result = await runLegacyStateMigrations({
    detected,
    now: () => 1234,
  });

  // The corrupt bytes must survive on disk (parse still fails after migration).
  const afterRaw = await fs.readFile(targetStorePath, "utf8");
  expect(afterRaw).toContain("corrupt trailing garbage");
  expect(afterRaw).toBe(corruptBytes);

  // No "Merged sessions store" change was committed against the corrupt target.
  expect(
    result.changes.some((c) => c.startsWith("Merged sessions store")),
  ).toBe(false);

  // The user is warned that the target store was left untouched because it is unreadable.
  expect(
    result.warnings.some((w) => /unreadable|corrupt/i.test(w)),
  ).toBe(true);

  // Legacy store is NOT deleted, so the data is still recoverable.
  await expect(
    fs.readFile(path.join(stateDir, "sessions", "sessions.json"), "utf8"),
  ).resolves.toContain("legacy-direct");
});
```

RED 기준 (수정 전): save 게이트 `(legacyParsed.ok || targetParsed.ok)` 가
`legacyParsed.ok=true` 로 통과 → `saveSessionStore` 가 손상 바이트를 legacy-only JSON 으로
덮어씀 → `afterRaw` 가 corrupt garbage 미포함 + `Merged sessions store` change 존재 +
unreadable 경고 없음 → 위 assertion 들이 실패.

GREEN 기준 (수정 후): target 손상 시 save skip + 손상 보존 + unreadable 경고 푸시 +
legacy 미삭제 → 4개 assertion 통과.

이식 가이드: `openclaw/src/infra/state-migrations.test.ts` 의 `describe("state migrations")`
블록 안에 추가. `createLegacyStateFixture` / `createTempDir` / `detectLegacyStateMigrations`
/ `runLegacyStateMigrations` 는 같은 파일에 이미 존재(재사용). 단독 검증:
`node scripts/run-vitest.mjs run --config test/vitest/vitest.infra.config.ts src/infra/state-migrations.test.ts`.

  target 이 읽히지 않으면 그 위치를 절대 덮어쓰지 않는다.

### 후보 2 — backup-corrupt-target-then-save

- **요약**: 손상 감지 시 save 전에 손상 파일을 `sessions.json.corrupt-{now}` 로 백업한
  뒤 기존처럼 legacy-only 로 save. 데이터 보존 + 마이그레이션 진행 둘 다.
- **change_scope**: S (백업 rename + 충돌 회피 + 경고 메시지).
- **tradeoff**: target 손상에도 마이그레이션을 끝까지 진행하므로 새 레이아웃이 즉시 완성된다.

  엮여 PR 이 커진다. one-thing-per-PR 관점에서 후보 1 대비 scope 증가. 후속 검토 가능.

### 후보 3 — transactional-migration-boundary

- **요약**: `runLegacyStateMigrations` 전체를 체크포인트/백업 디렉터리로 감싸 임의 단계

- **change_scope**: M (트랜잭션 프리미티브 도입, 다수 스토어 경로 영향).

### 커밋 메시지 초안
```
fix(infra): guard against overwriting corrupt target session store during migration

migrateLegacySessions reads the target agents/{id}/sessions/sessions.json
and merges it with the legacy sessions dir. When the target file is
corrupt, readSessionStoreJson5 swallows the parse error and returns
{store:{}, ok:false}, so the merge becomes legacy-only. The save gate
(legacyParsed.ok || targetParsed.ok) passes on legacyParsed.ok alone and
never checks targetParsed.ok, so the corrupt target is atomically
overwritten with the legacy-only store. Target-only session records (keys
with no legacy counterpart) are lost permanently and the corrupt file can
no longer be recovered by hand. Legacy corruption is already guarded
(warn + skip delete); target corruption was asymmetrically unprotected.

Skip the save (and the legacy delete) when the target store exists but is
unreadable, leaving the corrupt file and the legacy store both in place,
and push a warning mirroring the legacy-unreadable path. saveSessionStore
and readSessionStoreJson5 signatures are untouched.

AI-assisted: drafted with claude code (claude-opus-4-8).
```
