## 정정 (2026-05-20)

이 pre-sol proof 는 **무효**다. 최초 status `collected` 은 잘못된 측정이다.

real-behavior-proof 의 pre-sol 단계는 결함을 **실제 production flow** 를 통해
재현해야 한다 (cron-manual-run 은 실제 cron manual-run, gateway-map-size 는 실제
operator polling 으로 결함을 구동). 그런데 `retry-callback-throw` 시나리오는
`shouldRetry: () => { throw }` 라는 trigger 를 **probe 가 직접 주입**한다. 실제
openclaw 흐름이 아니라 `retryAsync` 함수를 직접 찌른 unit test 이므로 구조적으로
`collected` 만 낼 수 있다 — trigger 를 시나리오가 만들어 넣기 때문.

FIND-001 (retryAsync 콜백 무방비 누출) 을 production flow 로 정직하게 재현하려면
실제 caller (retry-policy channel runner / media-fetch / compaction) 를 통해야
하는데, cross-review 가 caller 전수 확인 결과 throwing 콜백을 주는 caller 가
0건이다 (전부 방어적). 즉 production-faithful pre-sol 의 정직한 결과는
`unreproducible` 이다.

결정 트리: `pre-sol unreproducible → CAND abandon (false-positive-by-reproduction)`.
이 proof 가 가린 신호 — cross-review 3 단계의 reproduction-realist 가 이미
