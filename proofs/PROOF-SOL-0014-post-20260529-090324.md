# PROOF — SOL-0014 (post)

**status**: `blocked-env` (probe-limitation; harness 자동 산출은 `unreproducible` 였으나 진단 후 정정)
**scenario**: `proof-CAND-045`

## 진단: 왜 unreproducible 이 아니라 blocked-env (probe-limitation) 인가

harness 의 `evaluate_post` 는 `without_fix.crashLockout && !with_fix.crashLockout` 을 collected 기준으로
삼는다. 본 실행에서 양 빌드 모두 `crashLockout=true` 라 자동 산출은 `unreproducible` 이 됐다. 그러나 이는
fix 가 결함을 못 닫아서가 아니라 **probe 가 fix-blind** 하기 때문이다(아래).

probe 의 crash 모델(`proof-CAND-045.py:108-109`)은 `writeFileSync(authPath, truncated)` 로 **probe 자신이
authPath 를 직접 truncate** 한다. fix(`replaceFileAtomicSync`)는 authPath 를 직접 건드리지 않고 sibling temp
파일에 write 후 atomic rename 하지만, probe 의 truncate 는 code 의 write 경로와 무관하게 authPath 를 망가뜨리므로
raw build 든 atomic build 든 동일하게 lockout 이 재현된다 → with/without 구분 불가.

probe 를 fix-sensitive 하게 만들려면 crash 를 "code 의 실제 write 호출 시점"에 inject 해
raw(=authPath 직접 write, crash hook 발화)와 atomic(=temp 파일 write, hook 미발화)을 구분해야 한다. 이는 모든
`writeFileSync`(auth-storage 의 named-import + fs-safe 의 default-import)를 단일 hook 으로 라우팅해야 가능하다.
tsx 환경에서 실측 진단한 결과 이는 근본적으로 불가능하다:

| 시도 | 결과 |
|---|---|
| ESM namespace 변형 (`fs.writeFileSync = ...`) | `Cannot assign to read only property` (module namespace frozen) |
| `module.registerHooks` 로 node:fs wrap | `node:fs` 가 `format=builtin / hasSource=false` → source-replace 불가 |
| default-import 객체 monkeypatch (`syncFs.writeFileSync = ...`) | base auth-storage 의 named-import write 를 `hookHitCount=0` 으로 전혀 가로채지 못함 (named binding ≠ default 객체) |

vitest 의 `vi.mock("node:fs")` 는 module-registry 레벨에서 named+default import 가 동일 mocked module 을
받도록 강제해 단일 crash hook 라우팅이 가능하다. tsx 에는 이 메커니즘이 없다. 따라서 tsx probe 의 fix-sensitive 화는
named-import 한계로 근본 불가 → 이 axis 의 with/without 권위 증거는 **regression test(vitest)** 가 담당한다.

## 권위 증거: Phase1 vitest RED→GREEN

`src/agents/sessions/auth-storage.test.ts` (fix diff 294819ced4 동봉). vitest 는 `vi.mock("node:fs")` 로
named+default `writeFileSync` 를 단일 crash hook 으로 라우팅한다:

- **RED (without fix, raw writeFileSync)**: persist 가 authPath 를 직접 write → hook 이 authPath 매치 →
  truncate + throw → 다음 reload 의 JSON.parse throw → loadError → getApiKey undefined → lockout.
- **GREEN (with fix, replaceFileAtomicSync)**: persist 가 sibling temp 파일에 write + rename → hook 이
  authPath 매치 안 됨 → 미발화 → set() 정상 완료 → auth.json 에 seed 값 보존.

즉 raw vs atomic 의 with/without delta 는 vitest 에서 정확히 입증됐다. 본 post-sol scenario 의 measurements 는
"probe 가 양 빌드 동일 lockout 을 보였다(=probe-limitation)" 는 사실 자체의 증거로만 보존한다.
